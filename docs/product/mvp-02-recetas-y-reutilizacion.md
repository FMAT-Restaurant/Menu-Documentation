# MVP-2 — Recetas y reutilización

## 1. Alcance

Este plan extiende la base de catálogo de MVP-1 para completar los modos de contenido requeridos, administrar recetas reutilizables con revisiones y permitir referencias versionadas a otras ofertas. Participan Front y Back.

Al terminar esta etapa, REQ-MENU-CONT-001 queda cubierto para INLINE, INVENTORY_ITEM, PREPARATION y CATALOG_OFFER. REQ-MENU-CONT-004 queda cubierto para crear y fijar una referencia de oferta, incluida su regla de no sumar basePrice al precio de la oferta contenedora. La materialización al retirar una entrada se entrega en MVP-3 junto con REQ-MENU-ENTRY-004. Los cambios siguen docs/contracts/api-contract.md y las invariantes INV-MENU-005/008; no alteran recetas u ofertas históricas referenciadas.

| ID | Cuestión y efecto | Tratamiento del plan |

| OPEN-003 | Si RecipeLibrary se comparte entre menús o pertenece a uno; determina pertenencia y autorización. | Bloquea cerrar el alcance visible y la política de acceso. La ruta global aceptada no resuelve esta cuestión. No se elige semántica Front/Back hasta aprobación. |
| OPEN-001 | Moneda, precisión, redondeo y rangos de basePrice/priceDelta. | Oferta referenciada no suma su basePrice; valores monetarios fuera de las reglas resueltas siguen sin validación de dominio adicional. |
| OPEN-006 | Rangos, precisión, fracciones y unidades de cantidades de recetas/slots. | Bloquea reglas cuantitativas no definidas; se conservan los campos del contrato. |
| OPEN-008 | Validez estructural frente a actividad de alternativas. | Debe resolverse antes de afirmar que activar una composición con PREPARATION o CATALOG_OFFER cumple la condición pendiente. |
| Contrato API | AuthN/AuthZ y concurrencia permanecen abiertas. | La implementación no presenta ausencia de security como acceso anónimo/público; se determina control concurrente para revisiones con una decisión explícita. |
| Integración Inventario | No existe en docs/contracts una operación de búsqueda/consulta de InventoryItem. | Front solo consume una fuente de identificación que haya sido acordada; Back no crea endpoint de Inventory ni se atribuye propiedad de stock. |
